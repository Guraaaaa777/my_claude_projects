# 技術文書 頻出構文パターン集

診断([診断結果_2026-07-24.md](診断結果_2026-07-24.md))で読めなかった構文を中心に。
日本語に訳すのではなく、パターンを見た瞬間に「型」として意味が浮かぶことを目指す。

---

## 1. Although 〜, 主語(修飾語つき)+動詞〜, which is why 〜
譲歩(Although〜)→ 本題 → 結論(which is why〜)の3段構成。技術文書の「制約と対処法」の説明で頻出。

**型**: 「Aではあるが、(Aの条件下で)Bという状況が起こりうる。だからCが推奨される」

例文:
- Although the server retries failed requests automatically, clients that do not set a timeout may wait indefinitely, which is why explicit timeouts are strongly recommended.
- Although the API is backward compatible, applications that parse the response as a fixed schema may break when new fields are added, which is why clients should ignore unknown fields.

練習: 上の2文を見て、①譲歩されている事実 ②実際に起こりうる問題 ③推奨される対処、の3つを日本語で一言ずつ書き出してみる。

---

## 2. Rather than A, B / instead of A, B
「Aする代わりにB」という対比。技術文書では「悪い設計 vs 良い設計」の説明でよく出る。

**型**: Aを否定し、Bを推奨する二択の提示。

例文:
- Rather than allowing a struggling service to be hammered with requests, a circuit breaker short-circuits calls once a failure threshold is crossed.
- Instead of polling the endpoint repeatedly, clients should subscribe to a webhook.

---

## 3. trade A for B(トレードオフ構文)
「Aを犠牲にしてBを得る」。設計判断の説明で頻出。

**型**: 完全な得はない、Aを差し出してBを得ているという構造。

例文:
- This approach trades a small amount of availability during normal operation for a much larger gain in resilience during outages.
- Caching trades memory usage for reduced latency.

---

## 4. since / given that 〜(理由・因果)
becauseよりフォーマルな理由付け。文の後半に置かれることが多く、見落としやすい。

例文:
- The client should surface the error to the caller instead of retrying indefinitely, since repeated retries under sustained load can worsen contention on the server.

→ 「, since〜」が出たら「これは理由の説明だ」とすぐ認識する。

---

## 5. 関係節が長く挿入されるパターン
主語の直後に関係節(that/which/who〜)が挟まり、動詞まで距離が空く。診断のSection Cで読み違えた原因。

**型**: [主語] + [that/which〜による長い修飾] + [本来の動詞]

例文分解:
> clients [that hold a reference obtained before the invalidation occurred] may continue to operate on stale data

- 主語: clients
- 関係節(修飾): that hold a reference obtained before the invalidation occurred(無効化前に参照を取得していた)
- 動詞: may continue to operate on stale data(古いデータを使い続ける可能性がある)

読むコツ: 関係節を一旦カッコに入れて主語と動詞だけ先に確定させる。「clients ( ) may continue to operate on stale data」→「クライアントは古いデータを使い続けることがある」がまず分かればいい。

---

## 6. if / unless による条件(リトライ・エラー処理で頻出)
- if those succeed, it closes the circuit
- unless the retry budget is exhausted

3. 新しいパターンに出会ったらこのファイルに追記する
